# Market Morning｜市場晨讀

給投資新手的繁體中文市場學習網站。每天用約 15 分鐘讀新聞、看公司、理解交易風險，逐步建立自己的判斷。

網站將市場新聞、每日精華、條件式觀察名單與投資入門整理在同一頁，並提供小額投資適用的部位風險計算器。

- **網站名稱：** Market Morning｜市場晨讀
- **儲存庫：** [Brian0927/market-morning](https://github.com/Brian0927/market-morning)
- **現有網站：** [市場晨讀｜投資學習室](https://brian-market-morning.orange-trail-6417.chatgpt.site)
- **介面語言：** 繁體中文
- **閱讀時間與時區：** 每日早上 08:00，Asia/Taipei

> 現有網站需要授權帳號登入。本專案供學習與研究使用，沒有下單功能，也沒有經回測證明的高勝率策略。`research.json` 與預設精華保留 **2026-10-21** 建站時的研究快照，不能當成今天的進出場建議。

## 目前功能

### 1. 每日精華

以卡片顯示已保存的重點、說明與來源連結，並標示資料時間。讀取 R2 裡的最新精華；尚未保存資料時，顯示程式內建的建站日精華。

精華內容由外部排程任務查核與撰寫，Worker 本身沒有呼叫語言模型，也不會自行產生 AI 摘要。

### 2. 六類新聞

| 分類值 | 顯示內容 |
| --- | --- |
| `taiwan` | 台灣市場 |
| `global` | 全球商業 |
| `macro` | 利率、匯率、能源 |
| `tech` | 科技與產業 |
| `company` | 追蹤公司 |
| `finance` | 金融與消費 |

開啟頁面、切換分類或按「重新讀取」時，由伺服器取得 RSS 標題。主要來源為 Google News RSS；台灣分類另有 Yahoo 股市，全球分類另有 BBC Business 與 CNBC。來源失敗時嘗試讀取該分類最後保存的新聞，並標示備援狀態。

多個可用來源以 `Promise.any()` 取第一個成功結果，**不是固定優先等 Google 失敗後才切換**。標題聚合不是完整新聞查核，請點來源原文確認內容。

### 3. 條件式觀察名單

建站快照包含 0050、00878、2330 台積電、2317 鴻海、2308 台達電；每項列出參考進場、目標、停損、未扣成本的風險報酬比、技術面、基本面、失效條件及來源。

這份名單由 `research.json` 在建置時嵌入。每日精華更新不會自動修改這份研究檔，也不會更新頁面上方的市場快照。

### 4. 投資入門

包括殖利率、本益比、EPS、ROE、獲利率、三張財報、現金流、K 線、折線圖、均線、支撐壓力、成交量，以及交易成本與資金管理。K 線與折線圖是教學示意，不是真實行情圖。

### 5. 部位風險計算器

輸入進場、停損、風險預算、可用現金與預估來回總成本後，估算股數：

```text
每股停損距離 = 進場價 − 停損價
風險限制股數 = (風險預算 − 預估總成本) ÷ 每股停損距離
現金限制股數 = (可用現金 − 預估總成本) ÷ 進場價
建議股數 = max(0, floor(min(風險限制股數, 現金限制股數)))
```

成本是使用者輸入的保守估計，系統不會查詢券商實際折扣。跳空、滑價或無法成交，可能使實際虧損超過試算。

## 技術與資料流程

這個 GitHub 版本整理自現有網站實際使用的 Worker 程式，未包含當初留在工作目錄中、未用於目前頁面的框架範本。

| 項目 | 實作 |
| --- | --- |
| 執行環境 | JavaScript ES Module Worker，預期部署到 Sites 的 Cloudflare Workers 環境 |
| 前端 | Worker 回傳 HTML，內嵌 CSS、瀏覽器 JavaScript、SVG 教學圖 |
| 本機工具 | Node.js 22.13.0 以上 |
| 額外套件 | 核心建置、預覽與測試不需要第三方 npm 套件 |
| 持久資料 | R2，binding 名稱 `BUCKET` |
| 使用者與服務存取 | 現有私人 Sites 平台的存取邊界 |
| 每日任務 | 外部 Sites 排程，與本儲存庫分開管理 |

```text
research.json ─┐
guide.json ───┼─ build.mjs ─ dist/server/index.js ─ Sites Worker
worker/market.mjs ┘                              │
                                                ├─ HTML → 使用者瀏覽器
                                                ├─ RSS → 最新新聞
                                                └─ R2 BUCKET → 精華與新聞備援

外部每日任務 → 查核新聞 → POST 精華／新聞 → GET 讀回確認 → 任務通知
```

## 快速開始

先安裝 Node.js 22.13.0 以上，並確認你有權存取這個儲存庫。

```bash
git clone https://github.com/Brian0927/market-morning.git
cd market-morning
node build.mjs
node verify.mjs
node preview.mjs
```

終端顯示 `Local: http://127.0.0.1:4173` 後，用瀏覽器開啟該網址。按 `Ctrl+C` 停止預覽。

若有 npm，也可以使用：

```bash
npm run dev
npm test
```

**不需要先執行 `npm install`。** 這個版本沒有第三方套件依賴。

### 本機模式與線上模式的差別

`preview.mjs` 是唯讀預覽轉接器，以空的 `env` 呼叫 Worker；沒有模擬 R2、Sites 登入或排程。它不轉送 POST request body，因此不適合拿來測試完整寫入 API。

- 本機可看頁面、教學、研究快照、風險計算器。
- RSS 需要網路；來源失敗且沒有 R2 備援時，會顯示錯誤提示。
- 精華會使用內建的 2026-10-21 版本。
- 寫入測試由 `verify.mjs` 直接呼叫 Worker，使用記憶體儲存替身。

## 如何修改內容

| 想修改的項目 | 要修改的檔案 | 是否重新建置／部署 |
| --- | --- | --- |
| 頁面文字、排版、新聞關鍵字、API | `worker/market.mjs` | 是 |
| 市場快照、股票名單與價位 | `research.json` | 是 |
| 投資入門文章 | `guide.json` | 是 |
| 最新精華 | 呼叫 `/api/brief` | 不需重建程式 |
| 新聞備援 | 呼叫 `/api/news-cache` | 不需重建程式 |
| 每天執行時間 | Sites 已連結的排程 | 需在平台更新，改 README 無效 |

每次改研究名單，都應更新日期、行情狀態、來源、成立與失效條件。不要只改進場價而保留舊停損與舊理由。ETF 除權息或分割時，也要確認價格基準。

## API 說明

以下路徑都相對於網站網址。線上存取還需要通過現有私人 Sites 的授權；本節範例只說明資料格式，不提供任何憑證。

| 方法 | 路徑 | 用途 |
| --- | --- | --- |
| GET | `/` | 網站首頁 |
| GET | `/api/news?group=taiwan` | 讀取分類新聞，取得新資料時也會保存 R2 備援 |
| POST | `/api/news-cache` | 保存排程取得的分類新聞 |
| GET | `/api/brief` | 讀取最新精華，沒有保存資料時回傳內建版本 |
| POST | `/api/brief` | 覆寫最新精華 |
| GET | `/api/instructions` | 讀取程式內的更新摘要與端點資訊 |

### 精華寫入格式

```json
{
  "date": "2026-11-01T00:00:00Z",
  "title": "每日市場晨讀",
  "items": [
    {
      "title": "重點標題",
      "text": "已核實的事實、可能影響，以及需要留意的風險。",
      "url": "https://www.twse.com.tw/"
    }
  ]
}
```

- `title`：非空字串，最多 150 字元。
- `date`：能被 JavaScript 日期解析的時間；建議帶時區的 ISO 8601。
- `items`：1～12 項；每項標題最多 200 字元、說明最多 2,000 字元。
- 每項 `url` 必須是以 `https://` 開頭的字串。
- request 文字長度限制為 40,000；程式另會檢查 `Content-Length`。

成功回傳包含 `saved`、`date` 與 `count`。寫完必須再 GET，核對日期、標題與數量，不能只憑 POST 成功就假設結果完全正確。

### 新聞備援寫入格式

```json
{
  "group": "company",
  "items": [
    {
      "title": "公司公告標題",
      "url": "https://www.twse.com.tw/",
      "date": "2026-11-01T00:00:00Z",
      "source": "原始公告來源"
    }
  ]
}
```

- `group` 必須是前述六類之一。
- `items`：1～20 項；新聞標題最多 500 字元。
- 每項需要 HTTPS 連結與可解析的發布日期；`source` 最多保存 100 字元。
- request 文字長度限制為 120,000。
- 儲存時間由伺服器填入 `fetchedAt`；每項 `date` 則應保留原始發布時間。

### 常見回應

| 狀態 | 可能原因 |
| --- | --- |
| 200 | 讀取或保存成功；仍要檢查內容日期與狀態 |
| 400 | 分類不存在、JSON 或欄位格式不符 |
| 404 | 未定義的路徑 |
| 405 | `/api/brief` 使用未支援的方法 |
| 413 | 精華 request 超過長度限制 |
| 502 | 新聞來源全部失敗，且沒有可讀取的備援 |
| 503 | 寫入時 R2 未連接，或精華儲存暫時無法讀取 |

Sites 平台可能在請求抵達 Worker 前要求登入或拒絕存取，這類結果不由上述程式內的狀態表決定。

## 資料儲存

R2 binding 名稱是 `BUCKET`，目前使用下列 object keys：

```text
latest-brief.json
news-taiwan.json
news-global.json
news-macro.json
news-tech.json
news-company.json
news-finance.json
```

目前每個 key 保存最新一份資料，沒有歷史版本、去重資料庫或多使用者資料隔離。重新部署程式不等於清空 R2；但把程式複製到新網站，也不會自動複製 R2 資料。

## 每日更新與手機通知

原站建立時已設定每日 **08:00 Asia/Taipei** 的 Sites 排程，名稱為「每日08:00市場晨讀與投資精華」。它是平台上的獨立資源，**不會因為 clone 或 push 這個儲存庫就自動建立或執行**。此 README 不保證該外部排程在你閱讀時仍處於啟用狀態。

預期流程：

1. 確認原站仍為擁有者私人存取，取得平台支援的服務存取方式。
2. 讀 `/api/instructions`，並按 [UPDATE-WORKFLOW.md](UPDATE-WORKFLOW.md) 的要求查核過去 24 小時新聞。
3. 先讀公司 IR、交易所、央行等原始資料，再搭配可信媒體。
4. 寫入六類新聞與 3～5 點繁體中文精華。
5. GET 讀回確認；失敗時保留舊資料並回報。
6. 在任務結果提供重點、更新狀態與網站連結。

台灣 08:00 尚未開盤，因此台股應使用最近交易日收盤；美股應標記當地交易日期。休市、盤中、延遲與資料缺漏必須說明。

網站本身沒有 Web Push、service worker 推播訂閱、寄信或簡訊程式。手機通知依賴外部排程平台、帳號支援及手機通知權限；08:00 是開始執行時間，不能保證恰在 08:00 收到完成通知。

## 部署與 GitHub 的關係

`.openai/hosting.json` 保留原站的 `project_id` 與 `r2: "BUCKET"`，供授權維護者識別原本的 Sites 專案。project ID 不是存取憑證，不能用它代替登入。

### 更新現有 Sites 網站

需要使用有權限的 Sites 工具與來源同步流程：

1. 確認現有 project ID、擁有者與存取範圍。
2. 執行 `node build.mjs`、`node verify.mjs`。
3. 將對應來源同步到 Sites 的來源儲存庫。
4. 由同一份來源打包 `dist/`、保存版本並發布。
5. 確認部署成功，並檢查 R2、新聞及精華的讀回。

**GitHub push 不會自動更新原站。** 本儲存庫沒有 GitHub Actions、部署 webhook 或與原站連動的自動發布設定。原站的 Sites 來源庫與這個 GitHub 儲存庫是不同的儲存庫。

### 建立自己的新網站

不要把原站的 project ID 當作新站使用。先在自己的帳號建立新 Sites 專案，改用平台回傳的 ID，配置自己的儲存與存取權限，再發布。Cloudflare 原生部署等其他平台也需要另外補上部署設定與授權層，不能直接將現有 Worker 公開上線。

## 存取權限與憑證

目前 Worker 的共用寫入端點依賴**原站的私人 Sites 存取邊界**；程式沒有額外的應用層 token 驗證、角色管理或 CSRF 防護。

- 保持原站僅擁有者可存取。若將網站改成公開或擴大分享，必須先設計寫入授權，否則可存取者可能覆寫精華與新聞。
- 在其他平台部署時，必須提供等效的驗證與權限控制。
- 服務憑證只能在受保護的執行環境中傳送；不要寫入原始碼、README、研究 JSON、Git remote URL 或 commit。
- `.gitignore` 排除 `.env*`、私鑰、本機狀態與建置封存。
- 此 repo 不包含原站 R2 裡的新聞或精華資料備份。

## 驗證方式

```bash
node build.mjs
node verify.mjs
node --check dist/server/index.js
```

現有 `verify.mjs` 涵蓋：首頁回傳、必要內容存在、內嵌瀏覽器程式語法、精華寫入與讀回一致，以及錯誤輸入被拒絕。

它不是完整端對端測試，沒有驗證真實 R2、線上登入、所有 RSS 解析情況、手機通知或每一個畫面尺寸。正式發布後仍應使用授權方式驗證實際來源與儲存。

## 常見問題

**為什麼看到 10/21 的價格？** 研究名單與市場快照是建置內容，需手動查核、更新 JSON 並重新發布；不要把它們當即時行情。

**按更新卻顯示舊新聞？** 外部 RSS 可能不可用，程式會改讀 R2 備援。請看讀取時間、文章發布時間與備援提示。

**精華沒有每天改變？** 先查外部排程是否執行、服務存取是否有效，以及 POST 後 GET 是否一致。單純重新載入頁面不會生成新摘要。

**clone 後為什麼沒有通知？** 通知不是 repo 內的功能，需要另行設定並授權平台排程。

**可以把網站放到 GitHub Pages 嗎？** 現有版本需要 Worker API 與 R2，不能直接當純靜態網站部署。需另外拆出後端或製作靜態匯出版本。

## 已知限制

- 非即時行情服務；沒有自動抓取股價、計算全市場技術指標或策略回測。
- RSS 使用輕量正規表達式取欄位，不是完整 XML parser；來源格式改動可能需要修正。
- 查詢採固定關鍵字，有些多詞查詢可能過窄而沒有結果，需調整查詢或由排程保存備援。
- 精華與新聞採最後一次寫入覆蓋，尚無歷史封存、版本衝突保護或復原介面。
- 新聞時間與 `fetchedAt` 含義不同，保存成功也不等於新聞事實已查核。
- 原始研究的風險報酬比未扣成本；各標的曝險可能重疊。
- 資料來源內容與商標權利仍屬各自權利人，本專案不授權重新散布新聞全文。
- 本 repo 尚未選定開源授權，請勿假設程式碼已採 MIT 等授權。
